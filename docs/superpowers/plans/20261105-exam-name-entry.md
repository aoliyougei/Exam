# 考试名称入口实施计划

> 执行时使用 executing-plans，逐项完成并核对结果。不委派 Agent，除非用户另行授权。

**目标：** 创建考试时支持唯一的 exam_name；首页输入名称进入现有考试页面；原链接及二维码保持直达。

**架构：** 保留 app.py 中已有生成逻辑，以标准库 SQLite 保存名称到 HTML 文件名的映射，数据库存于 storage/exams.sqlite3（非公开静态目录）。首页 / 改为考生入口，现有管理页移至 /admin。沿用 Flask、现有依赖，不引入数据库服务。

**需求依据：** 用户已确认新增考试名称选项、技能上传询问名称、首页输入名称进入、二维码仍直达，并同意名称唯一及保留管理页。

## 约束与兼容

- 新增 exam_name：有值时须为去除首尾空白后 1–120 字符的字符串；精确匹配、区分大小写，重名返回 409，不覆盖原考试。
- 为兼容旧客户端，不传 exam_name 仍可创建并通过旧链接或二维码访问，但不能按名称查找；显式传空值或非法类型返回 400。
- title 继续控制试卷展示标题，exam_name 用于查找，二者独立。技能每批上传前必须取得用户明确的 exam_name，已提供则不重复询问。
- 旧考试不自动回填名称、不修改既有 HTML 和二维码；首页说明旧考试使用原链接进入。
- 名称不是密码，查找不需要 API Key；不公开列出所有考试。
- 数据库唯一约束处理并发重名，参数化查询；名称不用于磁盘路径，HTML 模板自动转义。
- 映射与文件创建出现失败时不得保留可用的错误映射或覆盖已有考试；SQLite 错误不得静默当作“未找到”。
- Docker Compose 持久化 storage，Dockerfile 只增加确有需要的复制项；测试和构建只在 Docker 内执行。不使用宿主挂载（除非另获授权）。
- 当前目录不是 Git 仓库，不创建 worktree、不提交。

## 重点检查

名称空白/非字符串/过长；并发重名；重启后映射仍在；目标文件丢失；已有无名称 API 调用、考试链接和二维码回归。
